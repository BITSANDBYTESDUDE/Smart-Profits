2. Mandatory requirements (both used)

This idea satisfies both compulsory hackathon conditions by design.
  1. Network APIs: GSMA Open Gateway CAMARA APIs consumed exclusively through the Nokia Network-as-Code platform (SIM Swap, Number Verification, Location Verification, Device Status).
  2. AI Agent layer: the Smart Guard & Financial Agent orchestrates those APIs, combines them with financial context, and takes allow / step-up / freeze decisions — it is not a chatbot that only comments on Excel.

3. Problem

MENA merchants run the business from messy Excel, CSV, PDF and phone photos. They have no CFO and no bank SOC. The same login that diagnoses profit is the login that can leak the entire P&L after a SIM swap or a session from another country. Banks already buy network APIs. The SaaS that holds the merchant’s books usually does not.

4. Solution

Smart Profits is a bilingual merchant platform that cleans messy ledgers, diagnoses store health and profit leaks, answers questions from the currently open file, and protects that data with telco-grade identity and location. The Smart Guard AI Agent is a continuous security-and-finance agent: it analyses sales and watches network intelligence, then freezes sensitive uploads when the SIM or location is not trusted.

5. CAMARA APIs via Nokia Network-as-Code

APITriggerAgent decision
SIM SwapLogin, password reset, price change, payout / sensitive settingsRecent swap → do not trust SMS OTP; freeze session
Number VerificationLogin and step-up (silent 4G/5G, no SMS)Confirm the live network number matches the merchant
Location VerificationFinancial file upload and report exportMust match usual store/branch area or upload is blocked
Device StatusSame sensitive actionsDevice reachable / normal before allowing the action

All calls go through Nokia Network-as-Code (single developer access across operator CAMARA implementations). The product does not integrate operators one-by-one.

6. AI Agent orchestration

Merchant action (login / upload / export / price change)
  → Smart Guard Agent
     → Nokia NaC: SIM Swap + Number Verification + Location Verification + Device Status
     → Risk policy: ALLOW | STEP-UP | FREEZE
  → If FREEZE: block financial upload/export until network identity is confirmed

Example: if SIM Swap is recent or Location Verification is outside the store during an Excel upload, the agent does not ingest the workbook. Sensitive financial data stays off the platform until Number Verification succeeds on the trusted line.

8. Demo journeys

  • Trusted merchant: clean SIM, verified number, location = store → analyse Excel → “highest profit product” from that file.
  • SIM-swap fraud: attacker with a new SIM → freeze → no P&L download.
  • Strange location upload: file push outside branch geofence → Location Verification fail → upload blocked, explained in AR/EN.

9. Why this wins Theme 4

It is not a generic Excel copilot. It is a FinTech control plane for SMEs that spends CAMARA APIs the way a bank would: on identity, SIM integrity, and location — applied to the merchant’s own books, in Arabic, on 5G/4G. That is the GSMA + Nokia evaluation target: real regional fraud + programmable networks + an agent that decides, not a slide that lists APIs.
